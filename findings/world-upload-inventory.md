# CRD-025: test worlds A-D in the repo (inventory)

Checked 9 November 2026. What goes into git for the four test worlds, where it comes from, and what stays out.
The Test World (root `TestWorld/`, the `CordonaTest` content, `Test_P` paks) stays out: it needs work first.

## Going up (per world, X = A, B, C, D)

From `World Projects/World X/World_X/` (the Unreal 5.4 project):

| Path | Files | Size | Source |
|---|---|---|---|
| `AbioticFactor.uproject` | 1 | 176 B | the project file |
| `Config/Default*.ini` | 4 | about 13 KB | project settings (default map, maps to cook, chunking) |
| `Content/Mods/World_X/` | 16 | 300 to 450 KB | the world: loader Blueprint, map, Primary Asset Label, cube, light material, textures and materials |
| `Scripts/fix_collision.py`, `Scripts/fix_materials.py` | 2 | 11 KB | our editor helper scripts (the same in all four) |

The finished world, from `World Projects/Builds/` (copied from each project's
`Saved/StagedBuilds/Windows/AbioticFactor/Content/Paks/pakchunk9N-Windows.*`, renamed the way they are installed):

| Files | Size | Chunk |
|---|---|---|
| `WorldA_P.pak/.ucas/.utoc` | about 76 KB | 91 |
| `WorldB_P.pak/.ucas/.utoc` | about 81 KB | 92 |
| `WorldC_P.pak/.ucas/.utoc` | about 77 KB | 92 (see note) |
| `WorldD_P.pak/.ucas/.utoc` | about 87 KB | 94 |

These are byte for byte the files installed in the game's `Content\Paks\~mods\` (checked by MD5). Each chunk holds only that
world's own `/Game/Mods/World_X` assets (checked against the cook's chunk manifest), no game content.
Note: World C was rebuilt on chunk 92, the same as World B (its `PAL_World_C` says 92, not the planned 93); both mount and
work side by side (handoff, CRD-001). The cooked file is still `pakchunk92-Windows.*` in World C's `Saved/StagedBuilds`.

Total: about 2 MB, 104 files plus `World Projects/README.md`. No file is near GitHub's 50 MB warning, so no Git LFS or Release is needed.

## Left out

| What | Why |
|---|---|
| `Intermediate/`, `Saved/`, `DerivedDataCache/` | generated by the editor and the cook (about 400 MB per world) |
| `Build/` (`FileOpenOrder` logs, `pakchunklayers.txt`) | generated by packaging |
| `Packaged/` (about 240 MB per world) | the full packaged build: Unreal Engine binaries (`UnrealGame-Win64-Shipping.exe` is 132 MB, over GitHub's limit), engine `pakchunk0`/`global` paks. Not our work and not needed: only the world's own chunk is installed |
| `Content/Collections/`, `Content/Developers/` | empty |
| `Config/Layouts/` | empty |

## Checked for game data and third-party content

- No game assets: the assets reference only `/Game/Mods/World_X/...` and stock engine content (`/Engine/BasicShapes`,
  `/Engine/EngineMaterials/WorldGridMaterial`), which is not copied into the project.
- No mappings, nothing from `External Assets` or `External Mods`.
- The five imported textures (`Bricks`, `Concrete1`, `Metal1`, `Walkway`, `Wallpaper1`) were imported from
  `Custom Models/Ruins/*.tga` (a Wings 3D model dated 2013). Their origin is LuciDin's call (see the decision below).
- `World_X_L0.umap` still holds the old name `/Game/Mods/CordonaTest/Maps/CordonaTest_L0` as a string (left over from the copy);
  it is not a reference to the Test World's content.
- `Config/DefaultEngine.ini` has an Android File Server `SecurityToken` (a random per-project value Unreal writes, USB only,
  not included in shipping builds). Harmless.

## Decision

LuciDin, 9 November: yes to the list as above; the Ruins textures are his or free to redistribute, so they go up with the
worlds under the repo's CC0.
