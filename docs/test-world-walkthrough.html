Build a tiny test world for the Portal Hub

A minimal custom world, packaged as a patch pak, that the hub can load and send players to. It proves the whole chain and works as a template for other modders. No C++ needed. Numbers in brackets, like [1], point to the Sources at the bottom: Epic or UE4SS documentation, a community guide, or this project's own test results (marked as such, where the documentation is silent).

1Open the project

The project folder is TestWorld/AbioticFactor/ (git-ignored). It must be named exactly AbioticFactor. Its Config/DefaultGame.ini already turns on IoStore and chunk generation and lists the map to cook.

Why the map list matters: a level loaded as an instance is not part of any persistent map, so it is only packaged if it is listed here. [2]

2Make the map

Arrival point: the hub puts a pad at the arrive position, and players appear 215 units in front of it and 127 up. With arrive = { 0, 0, 0, 0 } the pad sits at the map origin facing +X, so players stand at (215, 0, 127), on the floor. [10]
Why Empty Level, not Basic: the Basic template adds a sky, fog, clouds, a directional light and an engine floor mesh. The lighting and atmosphere actors are global, so streamed in they would change the lighting of the whole game world, and the engine mesh would not be in your pak.
Why a copy of the cube: engine assets are not part of your chunk. If the floor used the original, it could be missing at runtime.

3Make the loader Blueprint

Do not build the loader as an Actor whose BeginPlay calls Load Level Instance (by Name). [2] It is documented, but in this game it reported failure and loaded nothing. [10] Print String is Development Only, so it prints nothing in the shipping game: do not rely on it to debug. [10]

6Install and connect to the hub

What the hub does behind that log: it finds the loader class with LoadAsset [5] (falling back to the asset registry's GetAsset [9]), spawns it at origin with SpawnActor [6], watches world.StreamingLevels for the entry whose PackageNameToLoad is your map and asks whether it is loaded and visible [7] (flushing level streaming now and then [8]), places the arrival pad at origin + arrive, and switches the hub portal on. Because the level is chosen inside the Blueprint, Lua never has to pass a text argument, which fails in this UE4SS build. [10]
Not a subfolder: on the Steam install a ~mods subfolder is not mounted. The pak must sit directly in Content/Paks.

The same thing as a config entry (what the editor writes for you):

worlds = {
    cordonatest_start = {
        loaderAsset = "/Game/Mods/CordonaTest/BP_CordonaTestLoader",
        loaderClass = "BP_CordonaTestLoader_C",
        level       = "/Game/Mods/CordonaTest/Maps/CordonaTest_L0",
        origin      = { 1100000, 1300000, 0 },
        arrive      = { 0, 0, 0, 0 },
    },
},
How the names fit together

Only some names have to match each other, and none of them is set inside Unreal except the asset paths.

NameWhere you set itMust match
World id, e.g. cordonatest_startOnly in the hub's config.lua (or the editor's Custom Destination box): as the key of your worlds entry and as the portal's destination. You invent it. Nothing in Unreal holds it.The worlds key and the portal's destination must be the same text. Do not start it with hub_.
loaderAsset, loaderClassIn the worlds entry.Your loader Blueprint's package path and its generated _C class.
levelIn the worlds entry.Your map's package path. Only used to recognise the level once loaded; the loader Blueprint is what loads it.
originIn the worlds entry.Free choice, but every world needs its own (below).
arriveIn the worlds entry.Free choice: where the arrival and return pad goes (x, y, floor z, yaw).
The map's name, e.g. CordonaTest_L0In Unreal.Not an id: it is not turned into the world id.

The hub connects a portal to a world through the shared id: the portal's destination is looked up as a key in worlds, and that entry names your loader and your level. The same id is stamped on the arrival pad the hub spawns, which is how the game's teleporter finds it. The arrival pad is also the way back: its destination is pointed at whichever hub portal you came through just before you step in.

Several custom worlds: each world is placed at its own origin, and the hub does not choose or check these for you. If two worlds share an origin (or sit close enough for their levels to overlap) they will occupy the same space. Give each world an origin far from every other world and from the Facility, for example 200,000 units apart. Only worlds that an enabled portal points at are loaded.
If something goes wrong
Log lineMeaning
the world's pak is not installed (no BP_CordonaTestLoader_C ...)The pak was not mounted (wrong folder, or no restart), was built without IoStore (it mounts but the game never loads it), or the Blueprint path or class in the config does not match.
loader spawned ... but never readyThe loader ran but the level did not stream in. Check the loader's Level is set, Desired Runtime Behavior is Standalone, the cooked loader contains the map path (step 5), and the map is in the Packaging list.
ready, but you fall or land in a wallAdjust arrive: z is the floor height, the last number is the way the pad faces.
(packaging) Unable to find package for cooking /Game/Mods/CordonaTest/Maps/CordonaTest_L0The map is not at that path (it was saved in the wrong folder). Move it into Content/Mods/CordonaTest/Maps.
(packaging) Failed to load '/Game/Mods/CordonaTest/...': Can't find fileThe map still references an asset you moved or deleted (for example a light asset dropped onto a cube). Replace it with a plain Point Light from Place Actors and package again. Usually harmless, but worth cleaning up.
(packaging) Stage Failed. Missing receipt ...-Win64-Shipping.target / Missing UnrealGame binaryThe packager thinks the project has code. Make sure the .uproject has no Modules entry (a Blueprint-only project has none), then reopen the editor.
The game crashes at start with Missing global shader ...The wrong pak was installed: pakchunk0 or global (engine content and a shader cache). Remove it and install only the pakchunk90 files.
The loader is not in your chunk (the chunk manifest lists only the map and meshes)The loader was never cooked. Add /Game/Mods/CordonaTest to Additional Asset Directories to Cook and package again.
Every UE4SS mod stops reacting after a Lua errorA Lua error inside any mod's hook can make UE4SS remove its tick hook (“removing hook!” in the log), and all game-thread work stops until the game is restarted. Disable the mod that errored and restart.
The game crashes on loadUsually a bad cook. Re-package, and check the chunk id is not 0.
What this exercise answered
  • A self-contained map plus a Level Instance loader Blueprint streams in at the configured origin: ready after 0.2 s in testing.
  • The hub's LoadAsset-first lookup finds the loader class.
  • The packaging settings that work for a new content chunk alongside the game's own: IoStore on, chunk id 90, the always-cook directory, and only the pakchunk90 triplet installed.
