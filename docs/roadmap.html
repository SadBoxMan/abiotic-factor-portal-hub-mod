✓Prove custom world hooking is doableA hub portal that loads and enters a world from another pakDone▸

Where it stands

Proven with our own Test World: the hub spawned the world's loader, the level streamed in (found loaded and visible at once, ready after 0.2 s), the arrival pad appeared at the right spot, the hub portal switched on, and the return trip was wired back to the hub portal. The hub's LoadAsset lookup found the loader class. On 16 Oct four more worlds (World_A to World_D) loaded side by side.

What it took

  • The loader must be a Blueprint based on Epic's Level Instance actor with its Desired Runtime Behavior set to Standalone. A BeginPlay graph that calls Load Level Instance (by Name) did not work in this game.
  • The pak must be IoStore. It loads from Content\Paks\~mods.

Where it stands

  • Engine assets are not part of your pak: copy the cube into your own folder.
  • The map must be listed under Packaging → maps to include, or it is not packaged.

If packaging fights back

  • UnrealPak on the cooked files directly, which is already in the tools folder.

✓World types: home and vignetteModders pick how their world behavesDone▸

Where it stands

Done 16 Oct, tested in game. A world is a home (default) or a vignette, set by WorldType on the loader Blueprint or type in the config.

  • Home (H_ in the game, like Temple of Stone, Torii and the Cabin): player homes. The in-vignette buff, an optional Leyak safety zone (on by default), no equipment lock, no separate exit.
  • Vignette (V_): puzzle worlds and adventures. Portal sickness locks equipment until the player uses the proper exit, which sets the world's own completion flag; the lock lifts and never comes back for that world. On-screen messages say what happened, and a test key clears the flag.

How the game does it

Both kinds hold the same Vignette_Zone, which gives the player Buff_InVignette. The equipment lock is Debuff_PortalSickness, applied only when the zone names a story flag (the Train's is TrainCompletedOnce; homes name none). A vignette can have several exits but only one is the proper one; reaching it sets the flag. Story flags are saved with the world as plain names, so removing a world's mod leaves one harmless unused name in the save.

6Full tutorialStarts once vignettes, lighting and skyboxes are figured outPlanned▸

What it covers

  • Making a world from start to finish, growing out of the Test World walkthrough.
  • The method, annotated: every step linked to Epic’s public Unreal Engine documentation (the API reference and the Blueprint node pages), so a modder sees not just what to do but why it works, and can check each claim at its source.
    • The loader Blueprint, the level it streams, and how the hub spawns it, polls for the level and places the arrival pad.
    • Packaging as an IoStore patch pak: chunk ids, always-cook directories, which files to install and which never to.
    • What was tried and why it fails (for example calling the streaming functions from Lua, or a legacy pak), so nobody repeats it.
  • An Advanced section for the small details modders trip over: transparency (Masked, not Translucent), bulk-setting materials, tiling and sub-region UVs, scrolling textures, lighting for a custom world, and a custom skybox.
  • Writing the Lua for your own world by hand, for modders who don't want to use the GUI program.
  • For people reading the code: a short “how the code is organised” guide and a contributing note.

Watch-outs

Cite only public sources, mark what is inferred from testing rather than documented, and keep it in step with the walkthrough.

7Mod packagingThe mod, the program and everything else, for Nexus ModsPlanned▸

Condense into one mod

  • Keep, for function: the hub mod and the editor.
  • Move out, for debugging: the logger, the material lab and the old proof of concept. Ship them as a separate dev/ folder, or fold the useful bits into the hub behind a debug = true switch. The lab is a good learning resource, so keep it easy to find but clearly labelled.
  • Release shape: one PortalHub folder in the Mods folder, an optional tools folder, a version number and a changelog.
  • Watch-out: UE4SS loads Lua modules slightly differently from a normal setup, so test the combined layout carefully, including hot reload.

A friendlier GUI that antivirus leaves alone

  • A: Keep the PowerShell script. Plain text, visible console, readable by anyone. Least suspicious form of script, though never zero-risk.
  • B: A single-file web editor (HTML) in Edge or Chrome that reads and writes config.lua directly. No executable, no script, no install, so almost no antivirus risk. Needs a Chromium browser and a one-time file permission each session.
  • C: A compiled .exe (for example .NET). Looks polished, but unsigned executables are flagged far more often than scripts, and signing certificates cost money.
  • D: No external tool. Only presets and hand-editing.

Recommendation: B, keeping A as a fallback.

World settings in the GUI

  • Find installed worlds by itself. A world pak's table of contents (.utoc) is readable without the game: it lists the world's folder, loader and map, so the GUI can add a world in one click and pick a free position and slot.
  • Show the map maker's settings. Those are inside the compressed part of the pak, so the hub reads them in game and writes a small catalog file after one launch, which the GUI shows. (Alternative: map makers ship a small settings file next to the pak.)
  • Let players change them for their install, to spice up a playthrough: the Leyak safety zone, which buff the proper vignette exit gives, letting the world have weather, and more as they are found.

Hub layouts and presets

  • Presets for the Nexus page: ready-made config.lua files such as “Story worlds”, “All worlds”, a colour-themed hub, or an “Anteverse tour”, with “Load preset” and “Save as preset” in the editor. Test each in game first and leave out the DLC areas.
  • World mods that put their own portal in the hub: the original “hard-baked layouts” idea. Now largely covered by worlds describing themselves; what remains is a rule for two worlds wanting one slot (first come, a priority number, or the player chooses), and keeping ids from colliding.

How the pieces fit (decided 14 October 2026)

  • A world describes itself. The map maker sets the world's details in their own project, as variables on the loader Blueprint: title, type (vignette or home), lighting, arrival point, exit, and later music. The hub reads them; it does not have to be told.
  • The Portal Hub only connects worlds. Its job is putting each world's portal in the Portal Hub room. Its config shrinks to which world goes in which slot.
  • Some Lua is expected. Making a world behave like a vignette needs a small runtime script; the tutorial gives modders those tools, so a world can also be used without our hub.
  • Portal locations elsewhere in the Facility come much later. For now every world's portal goes in the Portal Hub room.
